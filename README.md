# inmc-monster

Paper 서버용 커스텀 몬스터 플러그인. 몬스터의 스탯·장비·드랍·스킬·패턴·스폰 조건을 전부 GUI로 관리하며,
**바닐라 자연 스폰은 어떤 경우에도 그대로 동작합니다.**

| | |
|---|---|
| 서버 | Paper 26.1+ (Purpur·Leaf 등 포크 포함) |
| Java | 25 |
| 필수 의존성 | **없음** |
| 명령어 | `/몹` (별칭 `/monster`, `/mob`, `/몬스터`) |
| 권한 | `monster.admin` (기본 OP) |

---

## 설치

1. `inmc-monster-1.0.0.jar` 를 `plugins/` 에 넣습니다.
2. 서버를 시작합니다. `plugins/inmc-monster/` 에 설정 파일이 생성됩니다.
3. `/몹` 으로 GUI를 엽니다.

> **jar을 교체할 때는 반드시 서버를 끄고 하세요.**
> 실행 중인 서버 위에 덮어쓰면 JVM이 열어둔 zip 오프셋이 무효화되어,
> 아직 로드되지 않은 클래스에서 `NoClassDefFoundError` 가 발생합니다.

예시 몬스터(`example`)는 **비활성 상태로 배포**됩니다. 설치하자마자 필드에 뭔가 나타나지 않습니다.

## 빠른 시작

```
/몹                     GUI 열기
/몹 생성 부패한기사       새 몬스터 만들기
/몹 소환 부패한기사       내 위치에 소환
/몹 정리 전체            살아 있는 커스텀 몬스터 전부 제거
/몹 상태                 활성 개체·스폰 거부 사유·연동 상태
```

몬스터 관리창에서 **소환 알**을 받아두면 블록을 우클릭해 원하는 자리에 소환할 수 있습니다.
알에는 몬스터 ID가 아이템 데이터로 새겨져 있어, 이름을 바꾸거나 남에게 넘겨도 소환 대상은 바뀌지 않습니다.

## 핵심 개념

### 몬스터

`mobs/<이름>.yml` 파일 하나가 몬스터 한 종입니다. 적대·중립·평화 몬스터와 동물 모두 지정할 수 있습니다.

**`parent` 상속**으로 공통 스탯을 한 곳에서 관리합니다. 자식이 지정하지 않은 값만 물려받고,
순환 참조는 로드할 때 거부하며 로그로 알립니다.

**GUI에서 값을 바꾸면 이미 소환된 개체에도 즉시 반영됩니다.** 체력은 비율로 이어받으므로
전투 중에 최대 체력을 올려도 보스가 풀피로 회복되지 않고, 내려도 즉사하지 않습니다.
(엔티티 종류와 모델만 새로 소환해야 바뀝니다)

### 스탯

- **기본 스탯** — 바닐라 어트리뷰트. 소환할 때 엔티티에 직접 기록되고 서버가 그대로 적용합니다.
- **커스텀 스탯** — 치명타·관통·회피 등. 이 플러그인의 전투 계산에서 쓰이며,
  이름을 MythicLib `SharedStat` 과 똑같이 맞췄기 때문에 **MMOItems 장비에서 읽은 값과 그대로 합산**됩니다.

### 수식어 (접두/접미)

`강력한 욕심많은 좀비` 처럼 이름 앞뒤에 붙어 능력치를 바꿉니다.
**커스텀 몬스터뿐 아니라 평범한 바닐라 자연스폰 몬스터에도** 확률적으로 붙습니다 — 새 몬스터 정의를 만들지 않고도
필드가 균일하지 않게 됩니다.

수식어마다 **추가 드랍 테이블**을 가질 수 있습니다. 원래 드랍에 *더해서* 나오므로,
드랍 테이블이 없는 바닐라 몬스터에도 "수식어가 붙었을 때만 나오는 보상"을 만들 수 있습니다.

연산 순서는 **곱연산 먼저, 합연산 나중**으로 고정되어 있습니다. 합을 먼저 적용하면 무관한 `x1.2` 수식어가
`+5` 수식어를 조용히 증폭시켜, 각각은 약해 보이는 둘이 예상 밖의 조합이 됩니다.

### 스킬

**내장 23종** + 외부 연동 3종(MythicMobs · MagicSpells · 명령어).

<details>
<summary>내장 스킬 목록</summary>

| 분류 | 스킬 |
|---|---|
| 근접·이동 | 근접 강타, 도약 공격, 돌진, 지면 강타, 밀치기, 당기기, 순간이동 |
| 원거리 | 투사체 연발, 유도탄, 화염구, 번개 |
| 범위 | 독구름, 빙결, 폭발, 블록 감옥 |
| 보조 | 회복, 광폭화, 방어막, 포션 효과, 공포, 몬스터 소환 |
| 연출 | 연출(파티클/사운드), 메시지 |

</details>

각 스킬은 **자기 파라미터를 스스로 선언**하고 GUI가 그걸 읽어 편집 화면을 자동 생성합니다.
스킬마다 전용 메뉴를 손으로 짜면 23개가 서로 어긋나기 시작하기 때문입니다.

- **발동 조건 9종**: 소환 시 · 주기적 · 공격 시 · 피격 시 · 체력 감소 시 · 타겟 지정 시 · 플레이어 처치 시 · 페이즈 진입 시 · 사망 시
- **대상 선택 9종**: 자기 자신 · 현재 대상 · 가장 가까운 플레이어 · 무작위 · 최대 기여자 · 반경 내 전원 등
- **선딜(cast time)** 을 주면 예고 파티클이 뜨고, 피격 시 취소되게 만들 수 있습니다.

> 도약공격·돌진·당기기·순간이동·투사체 연발·유도탄은 **자기 자신을 대상으로 지정할 수 없습니다.**
> 자기에게서 자기로 가는 방향은 0이라 아무 일도 일어나지 않기 때문에, GUI가 애초에 그 선택지를 주지 않고
> 이미 그렇게 저장된 설정은 빨간 경고와 서버 로그로 알립니다.

### 패턴 / 페이즈

체력 구간마다 다른 행동을 줍니다. 페이즈에는 스탯 배율, 스킬 위력 배율, 모델 교체,
진입 동작(방송·소환·연출), 그리고 **순차 패턴 시퀀스**를 붙일 수 있습니다.

페이즈는 **한 방향으로만 진행**합니다. 회복으로 기준선을 다시 넘어도 되돌아가지 않습니다 —
회복할 때마다 등장 연출이 반복되면 전투가 망가지기 때문입니다.

### 드랍

`inmc-urb` 랜덤박스와 같은 방식입니다. GUI 빈 칸에 아이템을 놓고 확인하면 등록됩니다.

아이템은 **참조(ItemRef)** 로 저장되어 지급할 때마다 원본 정의로 다시 만들어집니다.
MMOItems에서 아이템을 수정하면 그대로 반영되고, 새로 발급한 것과도 정상적으로 겹칩니다.
참조로 표현할 수 없는 아이템은 스냅샷으로 보관합니다.

**분배 방식 5종**: 막타 · 최대 기여자 · 개인 지급 · 기여도 분배 · 바닥 드랍.
보스에 파티가 붙으면 막타 한 명이 독식하므로 기여도 기준을 권합니다.

각 항목은 **독립적으로 굴려지고**, 당첨된 것들이 배출 개수 상한까지만 잘려서 지급됩니다.
상한에 도달할 때까지 다시 굴리는 방식이 아니므로 "10% 확률"이 진짜 10%로 유지됩니다.

### 스폰

세 가지 경로가 있습니다.

1. **자연 스폰 치환** — 바닐라가 스폰하려는 몬스터를 확률적으로 커스텀 몬스터로 바꿉니다.
2. **스포너** — 좌표·반경 기반(지역형)과 월드에 설치하는 블록형.
3. **등장 조건** — 플레이어 행동에 반응. `/몹 소환`, 소환 알, 던전 API도 이 경로를 씁니다.

### 등장 조건 (트리거)

"나무 10개를 베면 10% 확률로 등장" 같은 규칙입니다. **13종**의 발동 종류가 있습니다:
블록 파괴·설치, 몬스터 처치, 플레이어 사망, 피해 입음, 낚시, 섭취, 제작, 인챈트,
날씨 변화, 시간 도달, 접속, 주기적.

누적 횟수와 확률이 **각각 따로** 걸립니다. 누적은 이벤트를 드물게 만들고, 확률은 플레이어가
타이밍을 정확히 계산하지 못하게 합니다.

## 안전장치

기본값에는 이유가 있습니다. 바꾸기 전에 읽어보세요.

### 치환 대상 스폰 사유는 `NATURAL` 하나뿐

#### 스폰 사유가 뭔가요

서버는 생명체를 하나 만들 때마다 **왜 만드는지**를 함께 기록합니다.

밤이 되어 어두운 곳에 좀비가 생기는 것도, 플레이어가 스폰알을 우클릭한 것도, 소 두 마리에게
밀을 먹여 송아지가 나오는 것도 서버 입장에서는 전부 "엔티티 생성"입니다. 하지만 **이유가 다릅니다.**
Bukkit은 그 이유를 `CreatureSpawnEvent.SpawnReason` 이라는 이름표로 붙여서 플러그인에게 넘깁니다.

26.2 기준으로 **47종**이 있습니다. 몇 개만 예를 들면:

| 이름표 | 언제 붙나 |
|---|---|
| `NATURAL` | 서버가 스스로 어두운 곳·동굴·초원에 몹을 배치할 때 |
| `SPAWNER` | 몬스터 스포너 블록이 몹을 뱉을 때 |
| `SPAWNER_EGG` | 누군가 스폰알을 우클릭했을 때 |
| `BREEDING` | 동물 두 마리가 번식해서 새끼가 나올 때 |
| `REINFORCEMENTS` | 맞은 좀비가 증원을 부를 때 |
| `INFECTION` | 주민이 좀비에게 물려 좀비주민이 될 때 |
| `CUSTOM` | 플러그인이 API로 소환할 때 (**우리 것 포함**) |

#### 이 플러그인이 그걸 쓰는 방식

치환 리스너는 서버가 만드는 **모든** 생명체마다 호출됩니다. 그 안에서 판정은 이 한 줄입니다:

```kotlin
val allowed = replacement.enabled && replacement.allowedReasons.contains(event.spawnReason)
```

즉 `allowed-spawn-reasons` 는 **"이 이름표가 붙은 스폰만 커스텀 몬스터로 바꿔라"** 는 화이트리스트입니다.

> 목록에 없는 스폰을 **막는 게 아닙니다.** 그냥 손대지 않고 지나갑니다.
> 바닐라가 하려던 대로 그대로 진행됩니다. 이것이 "바닐라 자연 스폰은 어떤 경우에도 정상 동작한다"
> 는 약속의 실제 구현입니다.

치환이 결정되면 두 갈래로 갈립니다. 이 차이가 아래 위험들의 원인이므로 먼저 짚습니다.

| 경우 | 동작 |
|---|---|
| 커스텀 몹의 종류가 **원래와 같음** (기본값) | 서버가 방금 만든 그 엔티티를 **그대로 꾸밈**. 이벤트 취소 없음 |
| 커스텀 몹의 종류가 **다름** | `event.setCancelled(true)` 후 **새로 소환** |

두 번째 경로는 원래 엔티티를 버리고 새것을 만듭니다. **서버가 그 엔티티에 걸어둔 계산이 함께 버려집니다.**

#### 왜 `NATURAL` 만 안전한가

`NATURAL` 은 세 가지 성질을 동시에 만족하는 유일한 사유입니다.

1. **바닐라가 개체수 상한(mobcap)을 관리합니다.** 월드에 몬스터가 이미 많으면 서버가 알아서 그만
   만듭니다. 우리가 아무것도 안 해도 상한이 존재합니다.
2. **플레이어의 행동 결과가 아닙니다.** 바꿔도 누군가 소모한 자원이나 만든 장치를 망가뜨리지 않습니다.
3. **자기 자신을 다시 트리거하지 않습니다.** 좀비가 생겼다고 좀비가 또 생기지 않습니다.

나머지 46종은 이 중 하나 이상이 성립하지 않습니다. 아래는 그 구체적인 내용입니다.

#### `REINFORCEMENTS` — 증식

바닐라 규칙: 좀비가 플레이어에게 맞으면 일정 확률로 근처에 좀비를 하나 부릅니다.
이 확률은 `SPAWN_REINFORCEMENTS` 어트리뷰트이고, **부를 때마다 부른 쪽과 불려온 쪽 모두 값이 깎입니다.**
그래서 바닐라에서는 몇 대 만에 자연히 멈춥니다.

여기를 치환하면 그 제동장치가 두 방향에서 풀립니다.

- **감쇠가 리셋됩니다.** 종류가 다른 몹으로 치환하면 원래 좀비는 취소되고 새 엔티티가 소환됩니다.
  깎여 있던 어트리뷰트는 그 취소된 엔티티와 함께 사라지고, 새 개체는 초기값을 들고 태어납니다.
- **개체가 오래 삽니다.** 커스텀 몹은 체력이 높습니다. 오래 산다 = 맞는 횟수가 많다 =
  증원을 부를 기회가 많다.

게다가 **증원 스폰은 mobcap을 확인하지 않습니다.** 자연 스폰 상한과 무관하게 나옵니다.
바닐라가 감쇠 하나로만 제동을 거는 구조인데, 그 하나를 우리가 매번 풀어주는 셈입니다.

결국 우리 `budget` 이 막긴 합니다. 하지만 그때는 이미 전역 상한(기본 400)이 좀비 증원으로 가득 차서
**서버의 다른 어느 곳에서도 커스텀 몬스터가 나오지 않는** 상태가 됩니다.
"왜 몬스터가 안 나오죠?" 의 원인이 이것입니다.

같은 구조: **`SLIME_SPLIT`** — 큰 슬라임이 죽으면 작은 슬라임 여러 개로 쪼개집니다.
하나 처치할 때마다 커스텀 몹이 2~4마리 나옵니다.

#### `BREEDING` — 플레이어가 자원을 써서 만든 결과물

소 두 마리에게 밀을 먹이면 송아지가 나옵니다. 그 스폰의 이름표가 `BREEDING` 입니다.

소를 치환 대상으로 삼은 커스텀 몹이 있으면, 송아지 자리에 그 몹이 나옵니다.
확률이 5%라도 스무 번에 한 번은 밀만 날아갑니다.

이게 특히 나쁜 이유는 확률이 아니라 **성격**입니다.
자연 스폰 좀비가 부패한 기사로 바뀌는 건 "오늘은 운이 없네" 지만,
밀 먹인 소가 몬스터가 되는 건 **"플러그인이 내 물건을 먹었다"** 입니다.

같은 성격의 사유들 — 전부 플레이어가 재료를 소모하고 특정 결과를 기대한 경로입니다:

`EGG`(달걀 던지기) · `DISPENSE_EGG`(발사기의 스폰알) · `BUCKET`(양동이에서 물고기 꺼내기) ·
`SHEARED`(버섯소 가위질) · `DUPLICATION`(알레이 복제) · `OCELOT_BABY` ·
`BUILD_IRONGOLEM` · `BUILD_SNOWMAN` · `BUILD_WITHER` · `BUILD_COPPERGOLEM`

#### `SPAWNER_EGG` · `COMMAND` — 관리 도구를 스스로 없애는 것

스폰알 우클릭과 `/summon` 입니다. 관리자가 "여기 좀비 하나 놔야지" 하면 부패한 기사가 나옵니다.

특히 곤란한 건 **문제를 추적할 때**입니다.
커스텀 몹이 이상하게 동작해서 순수한 바닐라 좀비와 비교하려는데, 바닐라 좀비를 놓을 방법이 사라집니다.

> 이 플러그인의 **커스텀 소환 알**은 이 경로가 아닙니다.
> `SpawnService` 가 `CUSTOM` 사유로 소환하고, 리스너 첫 줄에서 `CUSTOM` 은 즉시 반환하므로
> 설정과 무관하게 영향을 받지 않습니다.

#### `SPAWNER` — 파밍장 오염, 그리고 두 번째 무한 증식 경로

몬스터 스포너 블록(던전에서 발견했거나 플레이어가 옮겨 만든 경험치 파밍장)이 몹을 뱉을 때입니다.

파밍장은 구조상 **한곳에서 계속** 뱉습니다. 여기가 치환되면 네 가지가 동시에 일어납니다.

1. **청크 상한에 즉시 도달합니다.** `per-chunk-max: 6` 이므로 그 청크는 곧 거부 로그만 찍습니다.
2. **파밍장의 산출물이 바뀝니다.** 경험치와 썩은 살점을 기대하고 지은 장치가 커스텀 드랍을 뱉습니다.
   설계가 통째로 무의미해집니다.
3. **파밍장이 막힙니다.** 스포너 파밍장은 대개 "낙하로 체력을 1까지 깎고 주먹 한 대"로 설계됩니다.
   체력 200짜리 몹은 그 높이에서 죽지 않습니다. 죽지 않는 몹이 처치 지점에 계속 쌓입니다.
4. **스포너의 자체 제동이 풀립니다.** ← 가장 위험한 부분

4번을 자세히 보면: 스포너는 주변에 **자기가 소환할 종류의 엔티티가 몇 마리 있는지** 세어보고
많으면 쉽니다. 그런데 우리가 좀비 스포너의 좀비를 **다른 종류**의 커스텀 몹으로 치환하면,
스포너가 세어본 좀비 수는 **계속 0** 입니다. 쉬어야 할 이유가 영원히 생기지 않습니다.

`REINFORCEMENTS` 와 똑같은 구조입니다 — 바닐라의 제동장치를 치환이 무력화합니다.

#### `TRIAL_SPAWNER` — 바닐라 진행이 막힙니다

시험의 방(Trial Chamber) 스포너입니다. 여기는 **보상이 정해진 콘텐츠**입니다.
몹을 다 처치해야 금고가 열립니다.

커스텀 몹으로 바뀌어 난이도가 올라가면 방을 클리어할 수 없고, 그러면 금고도 열리지 않습니다.
플러그인이 바닐라 콘텐츠를 잠가버리는 셈입니다.

#### 변신 계열 — 원본의 데이터가 사라집니다

`INFECTION`(주민 → 좀비주민) · `CURED`(좀비주민 → 주민) · `DROWNED`(좀비 → 익사자) ·
`FROZEN`(스켈레톤 → 스트레이) · `PIGLIN_ZOMBIFIED`(피글린 → 좀피글린) · `METAMORPHOSIS` · `REANIMATE`

이건 "새 몹이 태어나는" 게 아니라 **기존 몹이 다른 몹으로 바뀌는** 경로입니다.
서버는 원본의 상태(주민의 거래 목록, 이름표, 장비)를 새 엔티티로 옮기는 중입니다.

우리가 이걸 취소하고 새로 소환하면 **그 이관이 중단됩니다.**
주민 치료(에메랄드 할인)는 서버 경제의 핵심 콘텐츠인데, 황금사과를 쓰고 치료했더니
거래 목록 없는 커스텀 몬스터가 나오는 상황이 됩니다.

#### 바닐라가 난이도를 계산해 짜둔 세트

`RAID`(습격 웨이브) · `PATROL`(약탈자 순찰대) · `VILLAGE_INVASION` · `VILLAGE_DEFENSE`(아이언골렘)

웨이브 5에 몇 마리가 어떤 구성으로 나오는지가 정해져 있습니다.
그걸 커스텀 몹으로 바꾸면 마을이 그냥 함락됩니다.

다만 이 넷은 **의도를 가지고 켤 만한 후보**이기도 합니다 — "우리 서버의 습격은 더 어렵다" 가
기획이라면 말이 됩니다. 그때도 커스텀 몹의 강도를 웨이브 난이도에 맞춰 조정해야 합니다.

#### `CHUNK_GEN` — 예산을 순식간에 태웁니다

새 청크가 생성될 때 함께 배치되는 동물들입니다. 두 가지 문제가 있습니다.

- 신규 지역에 소·양·돼지가 없으면 플레이어가 **초반 진행을 할 수 없습니다.**
- 청크 생성은 **플레이어가 없는 곳에서도 대량으로** 일어납니다 (사전 생성, 월드보더 확장).
  아무도 보지 않는 곳에서 예산이 전부 소모됩니다.

#### `CUSTOM` — 설정과 무관하게 코드에서 막혀 있습니다

플러그인 API로 소환한 모든 몹입니다. **우리 자신의 소환도 여기 포함됩니다.**

이걸 허용하면 커스텀 몹이 커스텀 몹을 치환하고, 그게 또 치환되는 무한 재귀가 됩니다.
너무 위험해서 설정으로 열 수 있게 두지 않았습니다 — 리스너 첫 줄에서 무조건 반환합니다.

```kotlin
// Our own spawns come through as CUSTOM. Letting them be seen here would allow one
// custom mob to replace another, forever.
if (event.spawnReason == CreatureSpawnEvent.SpawnReason.CUSTOM) return
```

#### 그래서 추가하기 전 체크리스트

새 사유를 켜기 전에 네 가지를 확인하세요. 하나라도 걸리면 켜지 마세요.

1. 이 경로가 **플레이어의 자원 소모**를 동반하는가? → 민원이 들어옵니다.
2. 이 경로가 **자기 자신을 다시 트리거**할 수 있는가? → 증식합니다.
3. 이 경로가 **관리자 도구**인가? → 자기 발등을 찍습니다.
4. 이 경로에 **바닐라 상한이 적용되는가?** 아니라면 우리 `budget` 만이 제동장치이므로
   확률을 아주 낮게 잡으세요.

그리고 켤 때는 **한 번에 하나씩**, 켠 뒤 며칠 지켜보고 다음 것을 켜세요.
동시에 셋을 켜면 문제가 생겼을 때 어느 것이 원인인지 알 수 없습니다.

#### 설정하는 법

`/몹` → 전역 설정 → **치환 대상 스폰 사유** 를 클릭하면 채팅으로 입력할 수 있습니다.
쉼표로 여러 개를 넣습니다.

```yaml
# config.yml
replacement:
  allowed-spawn-reasons:
    - NATURAL
    - PATROL      # 순찰대를 강화하기로 한 경우
```

> 이름을 잘못 쓰면 **조용히 무시됩니다** — 매칭되는 사유가 없으니 아무 일도 일어나지 않고,
> 설정이 적용된 것과 구별되지 않습니다. 그래서 인식하지 못한 이름은 서버 시작 시 경고로 남기고,
> GUI로 입력했을 때는 그 자리에서 알려줍니다.
> (자주 하는 실수: 번식은 `BREED` 가 아니라 **`BREEDING`** 입니다)

### 스폰 예산

월드/청크/플레이어 주변/전역 상한이 있습니다. **확률 스폰을 켜는 순간 필수입니다** —
관대한 확률 하나와 바쁜 밤이 겹치면 엔티티 수가 손쓸 수 없이 불어납니다.
모델 몬스터는 별도 상한을 씁니다(모델 하나가 여러 디스플레이 엔티티로 그려지므로).

거부 사유는 `/몹 상태` 에 누적 집계됩니다. **몬스터가 안 나오면 여기부터 보세요.**

### 연쇄 소환 깊이 제한

"A가 죽으면 B 소환, B가 죽으면 A 소환"은 두 줄이면 만들 수 있습니다.
소환된 몬스터는 부모의 깊이 +1을 물려받고, `max-spawn-generation`(기본 3)을 넘으면 거부됩니다.

### 장비 드랍 확률 기본 0%

몬스터에게 입힌 MMOItems 장비가 그대로 필드에 풀리면 경제가 붕괴합니다.
GUI에서 올릴 수는 있지만 0이 아닌 값을 넣으면 경고합니다.

### 커스텀 몬스터는 재시작을 넘어 살아남지 않음

재부팅마다 엔티티가 쌓이는 것을 막기 위한 정책입니다.
월드보스는 사망 이벤트의 **리스폰 예약**으로 되살립니다.
수식어만 붙은 바닐라 몬스터는 제거하지 않고 수식어만 해제합니다.

## 연동

전부 **선택 사항**이며 **리플렉션으로만** 접근합니다. 없어도 플러그인은 정상 동작하고,
설치되어 있으면 자동으로 붙습니다. 나중에 설치해도 리로드 없이 인식합니다.

| 플러그인 | 하는 일 |
|---|---|
| **MythicLib / MMOItems** | 몬스터가 입은 MMOItems 장비의 스탯이 실제 전투에 적용됩니다 |
| **BetterModel** *(권장)* / ModelEngine R4 | 커스텀 모델. 둘 다 지원하며 설치된 쪽을 자동 감지 |
| ItemsAdder / Nexo / Oraxen / EcoItems | 커스텀 아이템·블록 |
| WorldGuard / Lands | 지역·클레임 기반 스폰 조건 |
| Vault | 처치 보상 재화 지급 |
| PlaceholderAPI | `%monster_...%` 제공 |
| MythicMobs / MagicSpells | 해당 플러그인의 스킬·스펠 호출 |

### MMOItems 장비가 실제로 적용되는 방식

MythicLib의 `EntityStatProvider` 가 몬스터의 갑옷·주손·보조손에서 MMOItems NBT 스탯을 읽습니다.
다만 장비만 입혀서는 바닐라 데미지만 들어가므로, 몬스터의 공격을
**MythicLib 데미지 파이프라인으로 승격**시킵니다. 그래야 원소 데미지·치명타가 적용되고,
받는 쪽 플레이어의 방어·회피·원소 저항도 정상 작동합니다.

MythicLib이 없으면 같은 형태의 자체 계산으로 대체합니다.

## 던전 플러그인 연동 API

```kotlin
val api = MonsterAPI.get() ?: return   // 플러그인이 켜지기 전에는 null

// 태그를 붙여 소환하면 나중에 그 태그만 골라 정리할 수 있습니다
api.spawn("부패한기사", location, SpawnOptions(
    tag = "dungeon:room3",
    level = 30,
    countsTowardBudget = false,   // 던전 몹은 필드 상한과 분리
))

api.spawnGroup("썩은병사", location, amount = 5, spread = 4.0, options)

api.countWithTag("dungeon:room3")
api.killAllByTag("dungeon:room3")     // 던전 종료 시 정리
```

취소 가능한 이벤트 5종을 제공합니다:
`CustomMobSpawnEvent` · `CustomMobDeathEvent`(기여도 접근) · `CustomMobDamageEvent` ·
`CustomMobPhaseChangeEvent` · `CustomMobSkillEvent`

```
plugins/inmc-monster/
├─ config.yml            전역 설정 (주석에 각 값의 이유가 적혀 있습니다)

```

GUI로 편집한 내용은 1초 간격으로 모아서 저장합니다. YAML을 직접 편집한 뒤에는 `/몹 리로드` 를 쓰세요.

## 문제 해결

**몬스터가 안 나옵니다**
`/몹 상태` 의 "스폰 거부 사유" 를 먼저 보세요. `config.yml` 의 `debug: true` 를 켜면
판정 하나하나가 콘솔에 남습니다.

**적대 몬스터가 스폰되지 않습니다**
월드 난이도가 `peaceful` 이면 서버가 적대 몬스터 생성 자체를 거부합니다.
Multiverse 등으로 월드 난이도를 덮어쓰고 있지 않은지 확인하세요.
(`server.properties` 가 `easy` 여도 Multiverse 설정이 우선합니다)

**스킬이 발동하지 않습니다**
스킬 목록에 빨간 경고가 떠 있는지 보세요. 서버 시작·리로드 때도 로그로 알립니다.
가장 흔한 원인은 대상 선택이 스킬과 맞지 않는 경우입니다.

**수식어 몬스터 이름표가 조준해야만 보입니다 / 너무 가까워야 보입니다**
`display.affix-always-show-name` 이 기본 꺼짐입니다(켜면 맵 저편에서까지 보여 어수선해집니다).
조준 인식 거리는 바닐라 기본값이 매우 짧으니, 몬스터 스탯의 **`NAME_TAG_DISTANCE`** 를 올리세요.

**이름표에 체력을 표시하고 싶습니다**
`display.show-health: true` (기본 꺼짐). 체력은 보스바 쪽이 읽기 좋습니다.

**등장 조건이 반복 파밍됩니다**
쿨다운과 일일 제한을 확인하세요. 0으로 두면 나무를 심고 베기를 반복해 무한히 뽑을 수 있습니다.

`build/libs/inmc-monster-1.0.0.jar` 이 만들어집니다.
Kotlin 표준 라이브러리는 `com.inmc.monster.libs` 로 재배치되어 다른 플러그인과 충돌하지 않습니다.

테스트 **146개**가 함께 실행됩니다. 특히 다음을 검증합니다:

- 모든 설정의 **YAML 저장→로드 왕복** — 저장은 되는데 안 읽히면 "GUI가 저장을 안 했다"로 보이고 로그엔 아무것도 남지 않습니다
- 빈 스폰사유 목록이 "전부"가 아니라 `NATURAL` 로 떨어지는지
- 선택 플러그인 타입이 컴파일된 코드에 **직접 참조로 새어들어가지 않았는지** (바이트코드 스캔)
- 배포되는 `config.yml`·`affixes.yml`·`example.yml` 이 실제로 파싱되는지
- 드랍 롤러가 상한 절단을 재추첨으로 바꾸지 않는지 (희귀 드랍이 희귀하게 유지되는 근거)

## 알려진 제약

- **ModelEngine 연동은 실기 검증되지 않았습니다.** BetterModel은 실제 jar로 API를 확인하고 서버에서 동작을 확인했지만,
  ModelEngine R4는 설치본이 없어 코드만 작성된 상태입니다.
- **MythicMobs · MagicSpells 연동도 미검증**입니다. 미설치 시에는 조용히 무시하고 GUI에 사유를 표시합니다.
- 수식어의 `glow-color` 는 **켜기/끄기만 동작**합니다. 바닐라는 발광 색을 스코어보드 팀에서 가져오므로
  색상까지 구현하려면 팀 관리가 필요합니다. 절반만 구현하느니 색은 적용하지 않습니다.
